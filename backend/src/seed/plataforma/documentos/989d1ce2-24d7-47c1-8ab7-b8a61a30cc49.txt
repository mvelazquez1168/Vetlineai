Clinical Report Specification — ICIS

Versión: 1.0
Estado: Draft
Código: ICIS-REP-001

1. Introducción

Objetivo: Definir la estructura, contenido, reglas de generación y estándares de calidad de todos los informes clínicos generados por el Internal Medicine Clinical Intelligence System (ICIS), el sistema de apoyo diagnóstico y de triage/derivación para medicina general veterinaria.

Este documento establece el formato oficial para la documentación clínica producida por el sistema y garantiza consistencia entre casos, consultas y usuarios.

2. Filosofía del Informe

Todo informe deberá cumplir seis objetivos fundamentales:

1.  Documento Médico — debe servir como respaldo clínico del caso.

2.  Segunda Opinión — debe poder entregarse a otro colega sin necesidad de explicaciones adicionales.

3.  Documento Legal — debe representar fielmente la información disponible en el expediente.

4.  Documento Científico — debe exponer claramente el razonamiento clínico y la evidencia utilizada.

5.  Documento de Conocimiento — debe poder incorporarse a la Base de Conocimiento ICIS para apoyar futuros casos.

6.  Documento de Derivación — debe poder entregarse, sin ninguna edición adicional, a un especialista de otra área (gastroenterología, cardiología, dermatología, ortopedia/neurología, oncología, endocrinología, nefrología/urología, oftalmología, u otra) como base completa para continuar el caso. Esta es la función más frecuente y más crítica del sistema de medicina general.

3. Principios de Diseño

Todo informe deberá ser: clínicamente preciso, basado en evidencia, longitudinal, explicable, reproducible, auditable, profesional, libre de ambigüedades.

5. Report Architecture

Portada → Executive Summary → Patient Information → Reason for Consultation → Clinical History → Timeline → Physical Examination → Laboratory Analysis → Imaging Studies → Histopathology → Diagnostic Reasoning → Differential Diagnosis → Referral Recommendation → Therapeutic Plan → Clinical Evolution → Current Status → Recommendations → References → Appendices

6. Report Sections

CRS-001 — Cover Page: Incluye: Logo MedicaVet / ICIS (asset oficial: Logo_ICIS_MedicaVet.jpeg, isotipo circular "MedicaVet Clínica Veterinaria — Cartago"), nombre del informe, código del caso, fecha de emisión, veterinario responsable, versión del reporte, estado del caso, firma y certificación (CRS-023, pendiente de datos del profesional para ICIS).

Regla de mecanismo: dado que la Base de Conocimiento del proyecto no admite archivos de imagen sueltos como tipo de documento soportado, el archivo del logo debe estar disponible como adjunto directo en la conversación al momento de generar el informe. Si no está disponible, el sistema debe solicitarlo explícitamente al usuario antes de finalizar el documento — nunca omitir el logo en silencio.

CRS-002 — Executive Case Summary: ¿Qué paciente es? ¿Cuál fue el problema principal? ¿Cuál es el diagnóstico más probable? ¿Cuál es el estado clínico actual? ¿Requiere derivación, y a qué especialidad? ¿Cuál es el pronóstico? Máximo: una página.

CRS-003 — Patient Information: Nombre, especie, raza, sexo, edad, peso, BCS, propietario, veterinario remitente.

CRS-004 — Reason for Consultation: Motivo de consulta. Tiempo de evolución. Antecedentes relevantes.

CRS-005 — Clinical History: Narrativa cronológica. No copiar notas. Claude deberá sintetizar.

CRS-006 — Clinical Timeline: Cronología completa: consultas, laboratorios, estudios de imagen, procedimientos, cambios terapéuticos, derivaciones realizadas y su fecha.

CRS-007 — Physical Examination: Hallazgos clínicos organizados por sistemas. Estado general. Sistema afectado según motivo de consulta. Estado nutricional. Hidratación.

CRS-008 — Laboratory Analysis: Comparación longitudinal. Hemograma. Bioquímica. Electrolitos. Marcadores específicos según sistema sospechado. Interpretación automática. Gráficos evolutivos. Regla especial para Referral Report (CR-008): los valores de laboratorio deberán presentarse siempre como tabla con los valores originales, nunca resumidos ni parafraseados.

CRS-009 — Imaging Studies: Ecografía, radiología, estudios cardíacos, endoscopia, histopatología, otros según el caso. Cada estudio incluirá resumen, hallazgos, interpretación, comparación. Regla especial para Referral Report: las imágenes diagnósticas deberán insertarse directamente en el documento, no solo describirse.

CRS-010 — Diagnostic Reasoning: La sección más importante del informe. Explicar paso a paso cómo se llegó al diagnóstico o a la sospecha diagnóstica. No únicamente el resultado — también el razonamiento.

CRS-011 — Differential Diagnosis: Tabla con columnas Diagnóstico / Probabilidad / Evidencia / Estado.

CRS-012 — Evidence Matrix: Matriz completa. Toda afirmación deberá estar sustentada.

CRS-013 — Referral Recommendation: Nivel de manejo asignado (manejable en atención primaria / requiere derivación no urgente / requiere derivación urgente / información insuficiente). Especialidad de destino recomendada y justificación. Pregunta clínica específica que se espera que el especialista resuelva. Urgencia de la derivación, con justificación basada en las banderas rojas del sistema correspondiente cuando ese documento exista en la Base de Conocimiento. Cuando el nivel de manejo sea "manejable en atención primaria", esto se indicará explícitamente, no se omitirá.

CRS-014 — Therapeutic History: Todos los tratamientos, cronología, respuesta, cambios. Cuando el caso haya sido clasificado para derivación, esta sección se limita al manejo de atención primaria ya administrado.

CRS-015 — Clinical Evolution: Narrativa longitudinal, desde la primera consulta hasta la actualidad.

CRS-016 — Current Clinical Status: Estado calculado por el Clinical State Engine (ej. 🟡 Mejorando, 🔁 Derivado — en seguimiento por especialista), con explicación.

CRS-017 — Recommendations: Recomendaciones terapéuticas, estudios, seguimiento, monitoreo, información faltante, riesgos, y next steps específicos de la derivación cuando aplique (a quién contactar, qué llevar a la cita, urgencia).

CRS-018 — Prognosis: Favorable / reservado / grave / incierto / pendiente de evaluación por especialista, con justificación.

CRS-019 — References: Fuentes de literatura científica o guías clínicas utilizadas. Casos similares de la Base de Conocimiento con su identificador y un resumen de similitudes/diferencias. Documento de banderas rojas utilizado, cuando aplique.

CRS-020 — Appendices: Hemogramas completos, perfiles bioquímicos, informes de estudios de imagen, endoscopias, histopatología, imágenes seleccionadas, gráficos evolutivos, línea de tiempo clínica, matrices diagnósticas.

CRS-023 — Firma y Certificación

Cierre formal del informe. Contenido:

-   Nombre completo, colegiatura y clínica — se completan automáticamente a partir del código de médico registrado para el caso (o para la consulta más reciente relevante), consultando el Registro de Médicos compartido. Nunca se vuelven a solicitar si el código ya quedó registrado al abrir el caso, y nunca se escriben como valor fijo dentro de esta especificación.

-   Línea de firma (física o digital), siempre en blanco.

-   Fecha de emisión del informe.

Regla: si el código de médico no está registrado en el caso, o no existe en el Registro de Médicos, esta sección no puede completarse — el sistema debe resolver esa falta antes de finalizar el informe, nunca completarla con un nombre supuesto o el de un caso anterior.

Cuando el informe se genere como Referral Report (CR-008), esta sección debe indicar además que fue revisado y autorizado por el médico remitente identificado por su código antes del envío al especialista.

Ubicación en el flujo del informe (Report Architecture):

... → Recommendations → Firma y Certificación → References → Appendices

7. Reglas de Generación

El reporte deberá generarse utilizando toda la información acumulada en el chat del caso. No deberá omitir información relevante ni duplicarla innecesariamente. La narrativa deberá estar organizada cronológicamente. Toda inferencia de la IA deberá diferenciarse claramente de los hallazgos objetivos.

Cuando se genere un Referral Report (CR-008), el sistema deberá verificar explícitamente que la sección CRS-013 esté completa antes de considerar el informe terminado.

8. Export Formats

Microsoft Word (.docx), PDF, HTML, Markdown, Caso Docente, Caso para Base de Conocimiento. La estructura clínica será idéntica en todos los formatos.

9. Clinical Quality Checklist

Integridad: ¿Todos los datos del paciente están presentes? ¿Existe motivo de consulta? ¿Se documentó la evolución?

Evidencia: ¿Cada diagnóstico diferencial tiene sustento? ¿Las recomendaciones se basan en la evidencia disponible?

Derivación: ¿Se evaluó explícitamente si el caso requiere derivación? Si se recomienda, ¿se indicó especialidad y pregunta clínica específica? Si el reporte es Referral Report, ¿los laboratorios están en tabla con valores originales y las imágenes insertadas directamente?

Consistencia: ¿Existen contradicciones entre secciones? ¿Las fechas son coherentes? ¿La evolución coincide con laboratorios e imágenes?

Calidad: ¿El informe puede entenderse sin consultar el chat? ¿Puede usarse como segunda opinión o derivación sin ediciones adicionales? ¿Es apto para la Base de Conocimiento?

Logo: ¿El logo oficial está presente en el encabezado? Si el archivo de imagen no se adjuntó en la conversación, ¿se le solicitó explícitamente al usuario antes de finalizar el informe?

Firma: ¿El código de médico registrado corresponde a una entrada válida del Registro de Médicos? ¿La firma refleja el nombre, colegiatura y clínica obtenidos de ese registro, no un dato fijo o inventado?

Si alguna respuesta es negativa, Claude deberá advertirlo antes de generar la versión final.

10. Architecture Decisions

AD-009 — Single Source Report: el informe nunca será escrito manualmente; será ensamblado automáticamente a partir de los Clinical Components (CC-xxx), garantizando consistencia entre Dashboard, Reporte y Base de Conocimiento.

AD-010 — Progressive Report: el informe será un documento vivo; cada nueva consulta actualizará automáticamente las secciones correspondientes, manteniendo un historial de versiones.

AD-011 — Multi-Audience Reporting: a partir del mismo caso, el sistema podrá generar:

-   Versión Técnica — para colegas veterinarios en general.

-   Versión de Derivación — para el especialista de destino específico, con la sección Referral Recommendation como eje central.

-   Versión para Propietario — lenguaje claro, sin tecnicismos (v2).

-   Versión Académica — mayor detalle y referencias para docencia.

-   Versión para Base de Conocimiento — anonimizada y optimizada para búsqueda semántica.

Formato del Marcado en Secciones de Texto Libre

Las secciones de texto libre del informe (Historia Clínica, Razonamiento Diagnóstico, Evolución Clínica, contenido de apéndices, y cualquier otra sección sin una estructura de campos fija) se renderizan interpretando el marcado: negrita, cursiva, encabezados de nivel 2 (## Título), listas con viñeta y numeradas, y tablas en formato markdown.

Si el contenido de una de estas secciones se subdivide internamente, esa subdivisión deberá marcarse con un encabezado de nivel 2 (## Título) — nunca con negrita a modo de título.

La negrita (**texto**) queda reservada exclusivamente para destacar una palabra o frase dentro de un párrafo, nunca como sustituto de un encabezado.

Si el texto anuncia una cantidad de partes, elementos o pilares ("en base a X pilares..."), esa cantidad deberá coincidir exactamente con la cantidad que efectivamente se enumera a continuación. Ante la duda, no anunciar una cantidad específica.
